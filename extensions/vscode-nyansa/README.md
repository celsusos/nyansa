# Nyansa for VS Code

This extension connects VS Code to the self-hosted Nyansa control plane and CLI.
It gives developers a Nyansa activity-bar panel with an Assistant chat surface,
identity/session visibility, governed terminal launch, and workspace environment
controls.

## Development

From the repository root:

```bash
make dev-setup
make run-api
```

Open `extensions/vscode-nyansa` in VS Code and run the extension host with
`F5`.

## Install

For a local/private install from this repository:

```bash
make vscode-install
```

That packages a `.vsix` and installs it into the local VS Code profile. To install
a `.vsix` that an administrator has already shared:

```bash
code --install-extension nyansa-vscode-0.1.0.vsix
```

For organization-wide production distribution, publish the extension to one of:

- **Visual Studio Marketplace** for Microsoft VS Code users.
- **Open VSX Registry** for VSCodium, Gitpod, Eclipse Theia, and other Open VSX
  clients.
- A private internal artifact registry, then distribute the `.vsix` with device
  management, onboarding scripts, or your developer portal.

Before marketplace publishing, replace the placeholder `publisher` in
`package.json` with your registered publisher id.

## First Run

The extension launches the same governed CLI as the terminal flow. Each user must
have:

- The desktop CLI installed and runnable from VS Code's terminal environment.
- A control-plane token in the configured env file or environment variable.
- `nyansa.controlPlaneUrl` pointing at your control-plane URL.

The default env file is `.env`; production teams can set `nyansa.envFile` to a
workspace-local generated file when they do not want repo `.env` files.

Open the Nyansa activity-bar icon, use the **Assistant** view to ask the agent to
inspect or change the workspace, or start a full terminal session from the same
panel. Quick actions for `/help`, `/capabilities`, `/checkpoints`, and
`/sessions` use the same CLI command dispatcher as the terminal.

## Environment

The Assistant panel and Nyansa terminal share one environment builder:

- Values from the configured workspace env file.
- `nyansa.extraEnv` workspace settings.
- `nyansa.pythonPath`, exposed as `PYTHON` and prepended to `PATH`.

Use `Nyansa: Configure Environment` or the Assistant panel's Environment section
to set the Python interpreter, env file, CLI command, control-plane URL, token env
var, or extra `KEY=value` pairs.

## Commands

- `Nyansa: Open Assistant`
- `Nyansa: Configure Environment`
- `Nyansa: Start Interactive Session`
- `Nyansa: Run Prompt`
- `Nyansa: Open Control Plane`
- `Nyansa: Show Capabilities`
- `Nyansa: Refresh`

## Configuration

- `nyansa.controlPlaneUrl`
- `nyansa.tokenEnv`
- `nyansa.envFile`
- `nyansa.cliCommand`
- `nyansa.pythonPath`
- `nyansa.extraEnv`

The extension does not store control-plane tokens. Use environment variables or
the workspace `.env` file generated by setup/onboarding.
